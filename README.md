# Chaptale

Chaptale 是一个面向小说、剧本与长篇内容创作的创作工作台。

它希望把传统写作软件、资料管理工具、AI 助手和创作流程管理整合到一个更统一的空间里，让创作者可以围绕“作品”本身组织灵感、章节、角色、设定、时间线和修改过程。

## Chaptale 想解决什么问题

长篇创作往往不只是“写一段文字”。创作者通常还需要同时处理：

- 故事大纲
- 章节和场景
- 角色关系
- 世界观设定
- 术语、地点、组织、道具
- 时间线和伏笔
- 多版本修改
- AI 辅助构思、续写、润色和校对

这些内容经常分散在文档、表格、笔记软件、聊天记录和文件夹里。Chaptale 的目标是把它们收束到一个更适合创作的工作台中。

## 产品愿景

Chaptale 不是单纯的聊天机器人，也不是普通文档编辑器。

它更像一个为创作者设计的 IDE：

- 对程序员来说，IDE 用来组织代码、文件、引用、搜索和调试。
- 对创作者来说，Chaptale 希望用类似的方式组织章节、剧情、角色、设定、资料和 AI 协作。

也就是说，Chaptale 关注的是完整创作过程，而不只是单次文本生成。

## 当前核心体验

### 作品工作区

新建作品会建立章节、角色、设定、大纲和草稿目录，生成作品清单、创作守则与首章。也可以打开已有作品目录。没有配置模型时，文件编辑、资料管理和版本功能仍然可用。

### 长篇文本创作

CodeMirror 编辑器提供 Markdown 高亮、单击打开的标签页、查找替换、字数、双链和手动或自动保存。外部修改会触发重载或冲突对比，未保存稿有恢复入口。

### 结构化创作资料

资料库按作品内的 Markdown 与 frontmatter 组织角色、地点、组织、术语和伏笔。故事时间线支持自定义纪年与剧情顺序；角色关系画布支持查看、连线、编辑和布局保存。表单与画布修改同一份源文件，不建立另一套人物事实。

### AI 辅助创作

选区、章节和资产可直接加入 Agent 请求或冻结为本次参考。已有流程包括：

- 剧情规划与场景卡
- 初稿候选、逐块对比和作者确认
- 独立审查、原文定位和最小修订
- 章节结算、摘要与资产提议
- 版本回看、运行来源与实际用量追溯

正文和设定不会因一次对话被静默覆盖。上下文保持稳定前缀与追加历史，技能按需读取；Prompt Caching 按提供方能力适配，不发送后台预热请求，也不把未知缓存用量显示成零。

### 可扩展能力

设置中的“专员管理”可创建专属 Agent，管理本机或作品内的技能与资产模板。内容可作为版本化 JSON 包预览、选择导入或导出；导入专员默认停用并移除本机模型与权限配置，再由作者确认授权。

当前开放的是可检查的内容扩展，不提供任意代码插件、MCP 服务接入或插件市场。

## 适合谁

Chaptale 面向：

- 小说作者
- 剧本创作者
- 世界观设定爱好者
- 长篇内容创作者
- 使用 AI 辅助写作的人
- 希望更系统管理创作资料的人

## 项目状态

Chaptale 仍处于早期阶段，已有本地创作工作台与内容扩展闭环，不代表所有创作场景都经过实际用户验证。

首次启动提供可跳过的开始引导，也可以从“帮助”菜单重新进入。真实模型的创作质量与缓存计费、Windows 原生输入法、具体网盘客户端的兼容性仍需外部验收。状态栏仅显示本机可确认的保存与冲突信息，不把本地保存等同于远端同步完成。

## 本地开发

需要 Node.js 22 或更新版本，以及根 `package.json` 指定的 pnpm 版本。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

外部依赖版本统一维护于 `pnpm-workspace.yaml` 的 catalog；包清单使用 `catalog:`，内部包使用 `workspace:`。

```sh
pnpm typecheck
pnpm test:unit
pnpm lint
pnpm format:check
pnpm test:e2e
```

`test:e2e` 构建并启动真实 Electron，使用独立 HOME、USERPROFILE 和 user-data，不替换桌面桥，也不需要配置模型。需要跳过 Turbo 缓存验证生产构建时，直接运行 `pnpm --filter @chaptale/desktop build`。类型检查会重建共享契约，不应与依赖同一产物的构建或测试并行运行。

`temp/` 是独立预研与报告区域，不参与工作区包或正式测试，不应把其中的工程直接复制进应用。

## 设计原则

### 创作优先

工具应该服务于创作，而不是让创作者被复杂功能打断。

### 本地优先

创作内容对作者很重要，Chaptale 会优先考虑数据的可控性、可迁移性和长期保存。

### 结构清晰

长篇创作需要清晰的组织方式，尤其是角色、章节、设定和时间线之间的关系。

### AI 是助手，不是替代者

Chaptale 希望 AI 帮助创作者提高效率、整理思路、发现问题，但最终创作判断仍由作者掌控。

### 可长期扩展

小说、剧本、游戏文本、世界观设定等创作形式差异很大，Chaptale 会尽量保持核心简洁，把差异化能力留给扩展机制。

## 名称含义

Chaptale 可以理解为 Chapter 与 Tale 的组合：

- Chapter：章节、结构、长篇创作的组织方式
- Tale：故事、叙事、创作者真正想表达的内容

Chaptale 的目标，就是帮助创作者更好地组织章节，完成故事。
