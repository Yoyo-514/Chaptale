# 蓝图访谈法

把"我想写一个……的故事"收敛成可落地的作品蓝图。核心原则：**一次只问一个问题，用作者的回答驱动下一问**，不要一次抛出问卷。

## 访谈顺序

开场先用一问确认题材与目标读者（作者已明确说过的不重复问），再进入以下四轮。四轮按顺序推进，顺序不可颠倒——**后项依赖前项的答案**：

1. **核心冲突与结局意象**：先问"谁想要什么，什么在阻止他"，再问结局落在什么画面上（团圆的婚礼/雪地里的独行/烧毁的城）。冲突与结局是故事的两端，先钉住两端，中间的一切才有参照。
2. **主角欲望与缺陷**：欲望必须指向核心冲突（否则冲突与主角无关），缺陷必须让欲望难以达成（否则没有内在张力）。这一轮依赖第 1 轮：不知道冲突是什么，就无法判断欲望是否撑得起它。
3. **世界规则与代价**：只问与冲突直接相关的规则——主角为达成欲望要付出什么代价，规则允许/禁止什么。这一轮依赖第 2 轮：代价是针对"这个主角的这个欲望"定的，不是泛泛的设定填空。
4. **章节里程碑**：让作者说出前三个大的剧情节点（各一句话即可）。这一轮依赖前三轮：里程碑是冲突升级的刻度，没有冲突与代价就无从排布。

## 提问纪律

- **每轮只问一个问题**：得到回答后再决定下一问，不一次抛出多问；
- **优先出选择题**：作者答不上来时，给两三个具体选项帮他收敛（"结局偏向付出代价后的惨胜，还是彻底的失去？"），而不是重复开放式追问；
- 作者的回答含糊时，用他自己的措辞复述一遍请他确认，不替他补全。

## 蓝图输出模板

访谈结束后按此模板输出，逐项一行：

```markdown
# 作品蓝图：《暂定名》

- 题材：东方玄幻 / 都市悬疑 / ……
- 一句话故事：谁 + 想要什么 + 什么阻止他 + 代价是什么
- 主角欲望与缺陷：欲望 <一句>；缺陷 <一句>
- 核心冲突：<谁 vs 谁/什么，争的是什么>
- 结局意象：<一个具体画面>
- 前三个里程碑：① …… ② …… ③ ……
- 待作者决定：<访谈中未确认的项；全部确认时写"无">
```

示例（供参照粒度）：

```markdown
- 一句话故事：药铺学徒林晚想查清师父死因，而真凶正是庇护她的商会会长，代价是失去唯一的容身之处
- 主角欲望与缺陷：欲望：为师父讨回公道；缺陷：受人恩惠就不忍怀疑对方
- 结局意象：林晚烧掉商会的庇护文书，独自走出城门
```

## 停止条件

满足任一即结束访谈、输出蓝图：

- 作者明确表示"够了/先这样"；
- 模板六项全部有了明确内容（"待定"不算）。

## 禁止

- 不替作者做创作决定——作者未确认的项标注"待作者决定"保留原样；
- 不在访谈中途开始写正文或大纲。
