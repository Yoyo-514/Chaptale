# 章节结算

章节结算从一章已经写好的正文中整理摘要与事实，供后续章节参考。它适合在本章内容基本稳定后运行。

## 结算会产生什么

| 类型       | 主要用途               |
| ---------- | ---------------------- |
| 章节摘要   | 记录本章发生的主要事情 |
| 角色状态   | 整理角色经历或状态变化 |
| 伏笔推进   | 记录伏笔在本章的进展   |
| 时间线事件 | 将事件整理到故事资料中 |

生成的内容先进入结算批次。接受提议时，才把相应内容写入目标文件；摘要可在启动时另行选择自动接受。

## 发起结算

1. 保存目标章节，处理未保存或外部修改状态。
2. 选择「写作 → 结算本章」或进入右侧「结算」。
3. 核对章节、参考快照、来源与模型。
4. 决定是否勾选「本次自动接受摘要」。
5. 点击「生成待确认事实」。

::: tip 第一次使用
可以先不勾选自动接受摘要，读完一轮结果，了解模型会如何概括这部作品。该选项只针对本次摘要，不代表自动接受角色、伏笔和事件提议。
:::

## 逐项处理提议

在「结算批次」中选择一项提议，先看目标文件和理由，再比较“结算时版本”与“待确认内容”。

| 选择                  | 结果                             |
| --------------------- | -------------------------------- |
| 接受提议              | 将提议写入目标文件               |
| 编辑提议 → 编辑后接受 | 修正措辞或事实后写入             |
| 拒绝提议              | 不采用这一项内容                 |
| 放弃编辑              | 丢弃当前对提议的修改，回到原提议 |

检查时尤其留意：推测是否被写成事实、角色是否真的知道某条信息、事件顺序是否有正文依据，以及伏笔是否已经到了揭露时机。

## 完成结算

所有提议都接受或拒绝后，如果正文未发生变化，会出现「完成结算」。点击后批次标记为已完成。

只关闭窗口不会自动完成结算。以后可以从结算列表继续处理，也可以通过「查看运行」追溯本次任务。

## 正文或资料在中途变了

| 提示           | 如何处理                                           |
| -------------- | -------------------------------------------------- |
| 正文已变化     | 依据当前正文重新结算，未接受提议不会自动写回       |
| 目标资产已变化 | 保留当前文件，核对新内容；可拒绝旧提议后重新结算   |
| 失败 / 已取消  | 检查错误，确认当前文件状态后重试                   |
| 恢复接受       | 按界面提示继续处理被中断的接受操作，再核对目标文件 |

已经接受的提议属于已完成的写入。重新结算或拒绝其他提议，不会自动撤销这些变化。

结算与定稿用途不同：结算整理资料，定稿确认章节版本。详见[文档版本与定稿](/data/versions)。
