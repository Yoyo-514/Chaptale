# 配置模型

AI 对话、候选稿、独立审查和章节结算需要可用模型。模型服务由你自行配置；文件编辑、搜索和资料管理可以直接使用。

**入口：左下角「设置 → 模型」。**

## 准备连接信息

向所用模型服务确认以下信息。服务名称与 API 类型不是一回事，兼容接口需要按实际提供的协议选择。

| 项目 | 怎么填写 |
| --- | --- |
| 供应商 ID | 在本机配置中标识这个服务，按表单校验要求填写 |
| 显示名称 | 自己容易辨认的名称，例如“日常写作模型” |
| API 类型 | 与服务文档中的接口协议一致 |
| Base URL | 服务提供的接口基础地址 |
| API Key | 服务要求的凭据；无需鉴权的本地服务可按实际情况留空 |
| 模型 ID | 服务实际接受的模型标识，不能只填写一个自拟名称 |

当前表单提供四种 API 类型：**OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google Generative AI**。

## 添加供应商与模型

1. 点击「添加供应商」。
2. 填写 ID、显示名称、API 类型、Base URL 与所需 API Key。
3. 添加模型。可以拉取模型列表，也可以手动填写模型 ID。
4. 核对模型配置后保存供应商。
5. 在模型列表中选择「设为默认」。

拉取列表需要填写 Base URL 和 API Key；当前添加表单不支持拉取 Anthropic 模型列表，可手动添加。拉取失败也不一定表示模型无法调用，应先区分列表接口与生成接口的问题。

## 模型选项

| 选项 | 用途 |
| --- | --- |
| 默认模型 | 为未另行指定模型的操作提供默认选择 |
| 上下文窗口 | 描述该模型可容纳的上下文规模，应按服务实际能力填写 |
| 图像输入能力 | 指明是否接受图像输入；勾选不会为服务增加能力 |
| 高级生成参数 | 调整服务支持的采样等参数；不确定时保留默认值 |

候选、审查和结算确认窗口也会显示本次所用模型；专员还可设置模型偏好。排查“为什么用了另一个模型”时，应检查具体任务的选择，而不只看全局默认值。

## 验证配置

打开一部作品，在 Agent 中发一条简短消息，确认能够收到完整回复。随后再尝试需要工具或较长上下文的任务。

如果短消息成功、具体任务失败，检查任务的上下文长度、工具支持情况和运行错误。可在[运行记录](/ai/history)中核对实际模型。

## 常见连接问题 {#connection-problems}

| 现象 | 优先检查 |
| --- | --- |
| 提示没有可用模型 | 供应商是否保存、模型是否添加、所需凭据是否配置 |
| 鉴权失败 | API Key 是否正确，该地址是否属于这份凭据对应的服务 |
| 找不到模型 | 模型 ID、账号访问范围、Base URL |
| 拉取不到列表 | 是否支持列表接口；可尝试手动添加模型 ID |
| 请求格式不兼容 | API 类型与服务协议是否一致 |
| 上下文超限 | 缩减参考与附件，或选择实际支持更长上下文的模型 |

模型配置保存在本机 `models.json`，实际路径见「设置 → 配置文件」。其中可能包含凭据，不要用于公开的故障附件。

「设置 → 联网」控制搜索和网页抓取，与模型供应商配置分开。Agent 显示“离线”不表示模型请求在本机执行。
