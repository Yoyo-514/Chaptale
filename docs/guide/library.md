# 资料库与资产

资料库把角色、设定、伏笔、大纲、章节和场景卡按类型组织起来。这里的“资产”指带有类型与字段的创作资料，每一项都有对应的源文件。

## 查找与打开资料

从左侧活动栏进入「资料库」，选择所需类型，再按名称等信息筛选。想展开查看时，可以打开中央资料库；故事时间线和角色关系也从这里进入。

![资料库示例：类型筛选、资产卡片、源文件路径与诊断信息](/screenshots/library.png)

点击资产可查看内容，右键菜单提供「打开源文件」「加入写作参考」「与 Agent 讨论此资产」等操作。找不到资料时，先清除筛选，再查看归档状态和索引诊断。

## 新建资产

1. 选择「从模板新建」，或当前类型的新建入口。
2. 选择模板，例如主要角色、地点或伏笔。
3. 填写名称和需要的字段，确认目录与文件名。
4. 点击「创建文件」，再补充正文说明。

常用资料可以这样分工：

| 资料     | 适合记录的内容                           |
| -------- | ---------------------------------------- |
| 角色     | 姓名、别名、重要度、所属势力、人物关系   |
| 设定     | 世界观、地点、势力、能力体系、物品       |
| 大纲     | 故事整体走向、章节安排、细纲             |
| 伏笔     | 埋设位置、推进状态、最早揭露章节         |
| 场景卡   | 本场出场角色、地点、目标、禁忌和情绪基调 |
| 故事事件 | 事件顺序、发生时间、故事线及关联章节     |

已有文件也可通过目录树中的识别入口转换为资产。转换前检查类型与字段，避免只改了分类却遗漏后续视图需要的信息。

## 资料为什么能出现在不同视图里 {#asset-files}

Chaptale 读取 Markdown 文件头中的结构化字段，再据此生成资料库、时间线和关系图。表单与源文件编辑的是同一份资料。

下面是一个简化的角色文件示例：

```md
---
kind: character
title: 林晚
aliases: [阿晚]
importance: main
status: active
---

# 林晚

她曾在雾港守过三年的灯塔。
```

文件头也称为 **frontmatter**，放在两行 `---` 之间。优先通过模板与表单创建，手动编辑时保留合法的字段格式。

关系和事件是按已有字段展示的。在角色正文中写“顾沉是林晚的师父”，不会自动建立图上的连线；需要使用[角色关系](/guide/relationships)的编辑入口。

## 关联其他资料

模板中的角色、地点、章节等字段可以选择作品内资料。引用应能明确指向一个文件；同名资料、文件移动或缺失都可能造成未解决引用。

| 提示                 | 检查方法                                   |
| -------------------- | ------------------------------------------ |
| 含未解决引用         | 打开对应字段，确认目标文件存在且路径明确   |
| 冲突待处理           | 打开所列源文件，核对文件头与当前编辑状态   |
| 索引诊断             | 展开条目，按具体文件和错误修复             |
| 文件存在但不在列表中 | 检查资产类型、筛选条件、归档状态及文件位置 |

内部目录和模板定义文件不会被当作普通故事资料显示。

## 修改与移除

表单保存后，可以打开源文件确认变化。其他程序也修改了同一份资料时，先处理[文件冲突](/guide/editor#external-conflicts)再继续保存。

资料右键菜单提供「移到回收站…」。它会影响源文件；操作前检查其他资料是否引用它。仅想让一项资料退出常用视图时，可使用对应类型的归档状态。

AI 提出的资料变更显示为待确认提议。先比较当前资产与提议内容，再接受或拒绝；章节结算提议另见[章节结算](/ai/settlement)。
